## 阶段

1. **业务导航（低风险）**：主入口按缴费、法律文书、还款、沟通提醒、金山台账和系统管理划分，旧案件能力移入兼容档案。
2. **还款双工作区（中风险）**：`协议履约` 只查询已确认业务记录；`资料待办` 只查询待复核原始资料。两个页面拥有独立 URL、分页、筛选和选中状态。
3. **媒体惰性读取（中风险）**：进入或切换还款页面只加载结构化列表；只有人工点击具体资料或“查看原件/凭证”后才请求媒体内容。
4. **业务唯一性（高风险）**：回款说明文字只是截图上下文，不单独记账；回款必须人工关联已确认协议。金山更新使用协议事件保存的精确行号，债权人和债务人不再充当唯一键。
5. **旧库迁移（高风险）**：关闭默认自动建表；兼容 revision 停留在 `0007`、但后续模型曾提前建表的 SQLite 数据库，保留已有数据并直接升级到 head。
6. **验证与发布（低风险）**：覆盖接口筛选、状态统计、孤立事件、同当事人多协议、精确行更新、旧库真实副本迁移、静态交互、全量测试和生产页面验证。

## 还款状态机

- 原始协议或回款凭证：`OCR -> 待人工复核 -> 批准/驳回`。
- 协议批准：建立独立履约记录、上传协议、写入还款子表、创建未来分期提醒。
- 回款批准：必须指定协议；按凭证指纹去重，更新分期余额，取消已足额期次提醒，再更新原协议对应的金山行。
- 未选择资料时不读取原件；切换履约与待办页面不会触发媒体请求。
- 群 ID 只限制候选协议范围和消息发送位置，不代表案件或协议唯一归属。
